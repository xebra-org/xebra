# SDK and public API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@xebra/sdk` and a versioned public REST API (`/v1`, served on `api.xebra.exchange`) with an OpenAPI 3.1 spec, all running on the same code the bridge page and `/mcp` use.

**Architecture:** The pure logic now in `apps/web/lib` (chains, amounts, fees, addresses, message parsing) moves into `packages/sdk/src/core`. Transaction building is split from signing into `packages/sdk/src/build`. `apps/web/lib/api/service.ts` wraps core + build + network reads; `/v1` route handlers and the MCP tools both call it. Zod schemas in the SDK define every request and response; they generate `openapi.json` and type the SDK's HTTP client.

**Tech Stack:** TypeScript 5.7, zod 4.6.7, zod-openapi 6.0.2, vitest, Next 15 route handlers (apps/web), `@stellar/stellar-sdk` and `@mysten/sui` already in apps/web.

**Spec:** [`2026-11-11-developer-platform.md`](./2026-11-11-developer-platform.md) and the SDK/API outline given to the user on 2026-11-11 (routes, quote, build, track, claim; REST not tRPC; keys, idempotency, webhooks in plan 3; integrator fee in plan 4).

## Global Constraints

- Node >= 22, pnpm 9.15.0, Biome for lint and format; ESM only.
- Exact versions: `zod@4.6.7`, `zod-openapi@6.0.2`. The SDK keeps zod 4 to itself; other packages stay on zod 3.
- Amounts on the wire are decimal USDC strings with at most 6 decimals (`"12.5"`), regex `^\d{1,12}(\.\d{1,6})?$`, parsed to `bigint` 6-decimal units at the boundary with `parseUsdc6`. Never JS numbers.
- Chain ids on the wire: `"stellar" | "solana" | "sui"` plus the `EvmChainId` keys of `EVM_CHAINS` (`"arc"`, `"base"`, `"monad"`, ...).
- Non-custodial: no endpoint accepts a secret key or a signed transaction. Responses carry unsigned transactions only.
- Errors are RFC 9457 `application/problem+json`: `{ type, title, status, detail, code }`, `type` = `https://docs.xebra.exchange/errors/<code>`.
- CORS: `Access-Control-Allow-Origin: *`, methods `GET, POST, OPTIONS`, no credentials.
- No mainnet transaction is sent by an agent. Tests use recorded fixtures or fakes.
- Commits: plain messages, no co-author trailer (user's global rule). Run `sync` after each commit. Turbo with `--concurrency=2`. Node scripts need `NODE_OPTIONS=--no-network-family-autoselection`.
- The existing web suite (34 files, 399 tests on 2026-11-10) stays green after every task.

## Review Focus

1. **Recipient of the wrong family** (an EVM address sent to Solana, a G address to Base): 422 `invalid_recipient` naming the expected format, before any RPC call. Test in task 3.
2. **Route offered by config but not committed on the wrapper** (Arbitrum before its `commit_domain`): absent from `/v1/routes`, and `/v1/quote` answers 422 `route_unavailable`. Test in task 3.
3. **Circle's fee API unreachable:** 503 `upstream_unavailable` with `Retry-After`, never a quote built on a guessed fee. Test in task 3.
4. **Amount edge cases** (`"0"`, `"1e3"`, `"1.1234567"`, `"-1"`, below the route minimum, above `maxTransfer`): 422 `invalid_amount` or `amount_below_minimum`/`amount_above_maximum` with the limit in the body. Test in task 4.
5. **Sender cannot pay** (no USDC trustline on Stellar, balance short, Arc gas reserve): `POST /v1/transfers` answers 422 `insufficient_balance` with `have` and `need`, not a transaction that will fail on chain. Test in task 3.
