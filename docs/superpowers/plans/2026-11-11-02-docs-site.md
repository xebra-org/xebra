# Docs site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A separate, professional documentation site at `docs.xebra.exchange`: guides, concepts, a generated API reference with a request playground, type-checked SDK samples, and AI-readable output.

**Architecture:** New app `apps/docs` (Next 16 + Fumadocs), deployed as its own Vercel project. Content is MDX in `apps/docs/content/docs`. The API reference is generated at build from `packages/sdk/openapi.json`; SDK samples are compiled by Twoslash against `@xebra/sdk` from the workspace. The brand (obsidian and bone, Geist, the crossing mark) comes from the main site's tokens and files.

**Tech Stack:** `next@16.4.6`, `fumadocs-ui@16.18.4`, `fumadocs-core@16.18.4`, `fumadocs-mdx@15.5.3`, `fumadocs-openapi@12.6.0`, `fumadocs-twoslash@4.0.4`, `fumadocs-typescript` (pin the version current at execution), Tailwind CSS 4 (Fumadocs UI 16 requires it; apps/web stays on Tailwind 3).

**Spec:** [`2026-11-11-developer-platform.md`](./2026-11-11-developer-platform.md), section "Docs build".

## Global Constraints

- Everything in the overview's and plan 1's Global Constraints that applies (pnpm, Biome, commit rules, `sync`, turbo concurrency 2).
- Pin every dependency to an exact version.
- Design: before writing UI, invoke `high-end-visual-design` together with `minimalist-ui` (user's global rule); the project's palette wins on specifics. Colours: `--obsidian 228 16% 4%`, `--obsidian-raised 228 14% 7%`, `--bone 40 22% 96%`, `--signal 158 52% 60%`, `--alarm 10 68% 68%`; signal and alarm only for state. Fonts: copy `apps/web/app/fonts/geist-variable.woff2` and `geist-mono-variable.woff2`, loaded with `next/font/local` (no build-time Google fetch). Mark: `apps/web/public/icon.svg`.
- Dark is the default theme; a light theme exists and passes contrast too.
- Copy style: plain words, short sentences, no hype; every number on a page (fees, minimums, timings) is either generated from the API or dated.
- Every page answers to: builds with zero broken internal links, zero Twoslash errors, zero Biome errors.

## Review Focus

1. **A broken link or a stale anchor** after a page is renamed: the build fails (task 6 link check), not a 404 in production.
2. **A code sample that no longer compiles** after an SDK change: Twoslash fails the build (task 4).
3. **Fees or chain lists that drift from production:** pages that show them read `openapi.json` examples or call `/v1/routes` at build with ISR, never hard-coded tables (task 3, task 5).
4. **Phone width (375 px):** sidebar collapses, code blocks scroll inside themselves, no page-level horizontal scroll (task 6 screenshot check).
5. **Playground against production:** the API playground can only call read endpoints and `POST /v1/transfers` (which builds, never sends); it has no field for a secret key and warns that requests hit mainnet (task 3).
