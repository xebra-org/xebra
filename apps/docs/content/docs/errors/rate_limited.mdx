HTTP **429**. `type`: `https://docs.xebra.exchange/errors/rate_limited`

## What it means

Too many requests in a short time. The API allows 60 requests a minute without a key, counted per
calling address, or 600 a minute with a key, counted per key.


## What to do

Wait for the number of seconds in the `Retry-After` header, then ask again. Every answer also
carries `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`, so you can pace yourself
before you are refused. If you need more than 60 a minute, [get an API key](/docs/guides/api-keys).

If a response ever comes without `Retry-After`, back off: wait a few seconds, then double the wait
each time it happens again, up to about a minute.

In the SDK the error is an `XebraApiError` with `code: "rate_limited"`, `retryable: true`, and the
server's wait in `retryAfterMs`. Reads (`GET`) are retried on their own, honouring `Retry-After` up
to a minute; a longer wait is thrown at once for you to act on. `waitForDelivery` waits a 429 out on
its own.

## Example

```json
{
  "type": "https://docs.xebra.exchange/errors/rate_limited",
  "title": "Rate limited",
  "status": 429,
  "detail": "Too many requests: 60 a minute without a key. Send an API key for 600 a minute, or try again in 40 seconds.",
  "code": "rate_limited"
}
```

Every error has this shape. See [Errors](/docs/errors) for how to handle them.
