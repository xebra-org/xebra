title: Errors
description: Every error code the API answers with, what it means and what to do.
---

Every failed request answers with an [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem,
served as `application/problem+json`:

```json
{
  "type": "https://docs.xebra.exchange/errors/amount_below_minimum",
  "title": "Amount below the minimum",
  "status": 422,
  "detail": "Fees would take more than a tenth of this transfer. Send at least 2.4 USDC to Base.",
  "code": "amount_below_minimum",
  "minimum": "2.4"
}
```

- `code` is stable. Branch on it, not on `title` or `detail`.
- `detail` is a sentence written for a person. You can show it to your user as it is.
- `type` is the page for that code, on this site.
- Some codes add fields, such as `minimum`, `maximum`, `have`, `need`, `total` and `limit`.
  Amounts are decimal strings of USDC, like everywhere else in the API.

The SDK throws these as `XebraApiError`, with the extra fields on `err.extra`:

```ts twoslash
import { XebraApiError, createXebraClient } from "@xebra/sdk";

const xebra = createXebraClient();
try {
  await xebra.quote({ from: "stellar", to: "base", amount: "0.5" });
} catch (err) {
  if (err instanceof XebraApiError && err.code === "amount_below_minimum") {
    console.log(`Send at least ${String(err.extra.minimum)} USDC.`);
  }
}
```

The SDK adds three codes of its own, with `status` 0, for failures that never reached the API:
`network_error`, `timeout` and `invalid_response`.
